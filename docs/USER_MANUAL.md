# jue 用户使用手册：人机协同交互指南

**jue 没有独立的图形界面（GUI）或终端菜单（TUI）。你的对话窗口（或语音流）就是唯一的交互界面。**
你不需要记任何命令行参数，也不需要看底层 JSON。本手册专门教你：**如何用最自然的人类语言，让 Agent 帮你找内容、精准研读音视频、调度端侧声音与沉淀知识资产。**

> 💡 **配套演示**：本手册已配套认知击穿交互式 HTML 幻灯片，可在浏览器中双击直接演示：[`docs/USER_MANUAL-slides.html`](USER_MANUAL-slides.html)。

## 核心心智模型 (Mental Model)

```
                          人类 (你)
                             |
             +---------------+---------------+
             | (自然语言意图)                 | (紧急静音 / 物理打断)
             v                               v
       AI Agent (你的伙伴)         物理按键 (AirPods / 键盘 F8)
             |                               |
             +------------+                  | [0ms 直通急停，0 Token]
             |            |                  |
      [感知平面 Ingest]   [执行平面 Daemon]    v
             |            |           jue (后台无头 mpv)
             |            +---------> [本地声卡 · 毫秒级控制]
             |                               ^
             v                               |
    inspect / transcript / frame             +--- jue events (换章/曲毕/paused)
             |
             +---> 瞬态流式单帧 (<80KB, ~690 Tokens)
             |
             v
    调用 read_image 睁眼直视架构图与公式代码
```

- **复杂意图找 Agent（语义编排通道）**：“放点适合写代码的慢歌”、“总结这期演讲第 15 分钟说了什么”、“截一下第 3 分钟屏幕上的公式图并对比原话解释”；
- **肌肉记忆找物理键（硬件直通逃生口）**：电话来了、想立刻静音？直接轻捏一下 AirPods 耳机柄或按键盘媒体键（F8），**0ms 瞬间暂停，跳过大模型，不消耗任何 Token**；
- **下行直通与上行感知的对称闭环**：下行由人类手捏按键瞬间静音，上行由 `jue events` 即时捕获状态翻转并向智能体推送 `paused` 事件，Agent 在对话流中即刻心领神会；
- **视听感知三位一体**：`inspect` 查全局章节路标（<100 Tokens）、`transcript` 切片取声称级逐字原话（防机翻幻觉）、`frame` 瞬态抽取关键视觉帧（直通多模态视觉模型，击穿 PPT/白板信息黑洞）；
- **单实例自动接力与歌单连播**：每次点播新内容自动平滑替换；想连着听多首，Agent 一次把整组歌压进播放器的内存队列（`jue queue add`），由播放器自己一首接一首放下去，Agent 回完话就可以“离场”，不用一直盯着；整组放完时 `jue events --until queue_ended` 零轮询感知，按需续添；
- **报歌名就能放**：没有链接时，Agent 可以直接用 `ytsearch1:歌手 歌名` 在 YouTube 取第一条结果起播或排队，省掉一轮网页搜索；
- **细腰微外设**：jue 仅提供极简的感知平面与执行平面，Agent 负责所有多模态认知、格式排版与交互卡片呈现。

## 常用交互场景详述与实操示范（按 ROI 价值排序）

> **场景 ROI 排序原则**：认知杠杆（长文解构、事实去幻觉、时空追问、永久资产）> 专注心流（日常伴听、细粒度播控、自动续播）> 垂直辅助（多语种歌词精读）。

### 场景 1：长视频“全局路标 ➔ 定向分章点播”联动闭环 (ROI ★★★★★)

面对动辄 2~5 小时的技术大会录播或深度播客，最有效的收听方式是：**先查大纲路标，再选感兴趣的章节精确起播**。

```
          长视频链接 (2 小时)
                  |
                  v
       【第 1 步：查全局路标】
       “这期访谈主要分哪几部分？”
                  |
     Agent 执行 jue inspect (<100 Tokens)
     输出章节地图 (Chapters)
                  |
                  v
       【第 2 步：定向分章点播】
       “第 3 章看起来很有用，直接从那章开始放”
                  |
     Agent 计算该章起始秒数 (如 18:45 = 1125s)
     执行 jue play <url> --start 1125
                  |
                  v
       从第 18:45 秒精准起播，声音直接入耳
```

#### 实操对话示例：
1. **看目录**：
   > **你**：“*看看这个 Andrej Karpathy 的新视频主要讲了啥章节？*”
   > **Agent**：“*为您提取了章节路标：*
   > *- `00:00` 导言与分词原理 (Tokenization)*
   > *- `24:15` Byte-Pair Encoding 算法推导*
   > *- `58:30` GPT-4 词表特殊 Token 陷阱*
   > *- `1:25:10` 实践代码 Walkthrough*”
2. **点播特定章节**：
   > **你**：“*我对特殊 Token 比较感兴趣，从 58 分 30 秒直接放给我听。*”
   > **Agent**：“*已为您从 `58:30` 起播【GPT-4 词表特殊 Token 陷阱】，耳机已就绪。*”

### 场景 2：声称级事实核查与带时间戳精读 (ROI ★★★★★)

想知道视频里到底说了什么，但不想全文读入（避免浪费上万 Tokens），也不想听机器翻译的二手幻想。

#### 实操对话示例：
> **你**：“*第 15 分钟关于 KV Cache 动态分页，作者具体怎么论证的？给出原话。*”
> **Agent**：“*为您检索了 `14:00-17:30` 区间的原声字幕，核心结论是静态分配在高并发长文本下显存碎片化严重：*
>
> > [15:12] *“Static pre-allocation causes up to 70% memory waste due to fragmentation.”*
> > — [KV Cache Optimization (15:12)](https://youtube.com/watch?v=...&t=912s)
>
> > [16:04] *“By introducing virtual memory paging into GPU HBM, we achieve near-zero internal waste.”*
> > — [KV Cache Optimization (16:04)](https://youtube.com/watch?v=...&t=964s)*”

#### 关键交互点：
- **窗口相交过滤**：Agent 只切片目标 3~5 分钟的逐字字幕，上下文消耗严格锁定在 500 Tokens 以内；
- **带秒级时间戳链接**：点击链接直接跳到原视频该秒数验证原画与上下文，做到事实可核验。

### 场景 5：日常专注伴听、播控穿梭与歌单连播 (ROI ★★★★☆)

面向写代码、阅读、番茄钟工作或日常沉浸时的背景音流转。不论是网络流媒体（YouTube / 网易云）还是宿主机本地音频（如 `~/recordings/arch-review.wav`），Agent 负责挑歌、起播、呈现轻量卡片并提供全套播控与自主续播。

```
              用户意图：“放点专注写代码的 Lo-Fi，声音小点”
                                  |
                                  v
                    Agent 执行 jue play <url>
                    输出 2 行极简播放卡片 (带播放头与音量)
                                  |
            +---------------------+---------------------+
            |                                           |
    【细粒度播控与穿梭】                        【歌单连播与队列管理】
  “快进 30 秒” ➔ seek +30                   “连着放这几首” ➔ 逐条 queue add
  “跳到 14:05” ➔ seek 14:05                 播放器内存队列自动接力，Agent 即可离场
  “声音设为 40” ➔ volume 40                 “下一首 / 上一首” ➔ control next / prev
                                            整组放完 ➔ events --until queue_ended
```

#### 实操对话示例：
1. **起播与极简卡片**：
   > **你**：“*来点适合深夜写代码的氛围音乐，音量不要太大。*”
   > **Agent**：“*已为您起播背景音乐：*
   > **正在播放** · Midnight Coding Chillhop · YouTube
   > `🔊 音量 40% · 按 AirPods 耳机柄即可暂停，说“快进 30 秒 / 换一首 / 大点声”亦可控制`”
2. **播控穿梭与时空跳转**：
   - **跳过片头广告**：“*跳过前面 1 分半广告*” ➔ Agent 执行 `jue control seek +90`；
   - **细粒度回退**：“*倒回去 15 秒*” ➔ Agent 执行 `jue control seek -15`；
   - **绝对跳转**：“*跳到 24 分 30 秒*” ➔ Agent 执行 `jue control seek 24:30`（亦可绝对重置 `seek 0`）；
   - **探查进度**：“*现在播到哪了？*” ➔ Agent 执行 `jue status` 输出进度条。
3. **歌单连播 (播放器自驱动，零轮询开销)**：
   > **你**：“*放几首周杰伦的歌，连着放。*”
   > **Agent**：“*已为您排好 3 首：*
   > **正在播放** · 晴天 — 周杰伦 · 后面还有 2 首（七里香、稻香）
   > *说“下一首 / 上一首 / 后面还有什么”即可。*”
   *(Agent 依次执行 `jue queue add "ytsearch1:周杰伦 晴天"` 等三条：第一条立即起播，其余排队立返。之后由播放器自己接力，Agent 本轮即结束，不再占用任何 Token)*
4. **队列管理**：
   - **切歌**：“*下一首*” / “*上一首*” ➔ `jue control next` / `prev`（已是最后一首时如实告知“后面没有了”）；
   - **加歌**：“*把稻香也加到后面*” ➔ `jue queue add`，不打断当前曲目；
   - **看队列**：“*后面还有什么？*” ➔ `jue queue list`；
   - **清队列**：“*后面的都不要了*” ➔ `jue queue clear`，当前这首继续放完；
   - **整体换掉**：“*别放这些了，换成晴天*” ➔ `jue play`，整个队列被替换。
5. **放完自动续添**：
   > **你**：“*这几首放完了再给我续几首差不多风格的。*”
   *(Agent 执行 `jue events --until queue_ended` 阻塞等待，整组放毕的瞬间收到 `queue_ended`，再挑一组 `queue add` 续上，全程 0 轮询)*
6. **工作节奏与番茄钟停止**：
   > **你**：“*专注 25 分钟，到点叫我并停掉声音。*”
   *(25 分钟后，Agent 自动执行 jue control stop，音乐优雅停止并提醒休息)*
7. **本地录音审计**：
   > **你**：“*放一下昨天的会议录音 `tmp/meeting.wav`，从第 5 分钟开始听。*”
   > **Agent**：“*起播本地音频：`jue play tmp/meeting.wav --start 300`，原生同态播放。*”

#### 关键交互点：
- **极简卡片**：Agent 默认只给 2 行纯净卡片，不刷屏、不堆砌无用参数；
- **音源透明**：不管是网络 URL 还是本地 WAV/MP3 文件，交互形态完全统一；
- **连播下沉到播放器**：队列是播放器内存里的临时歌单，停止播放或播放器退出即消失，不留任何本地歌单文件；
- **零轮询感知**：整组放完用 `jue events --until queue_ended`，单曲边界用 `--until track_ended`，避免传统轮询导致的大模型 Token 浪费与时延；
- **硬件逃生**：任何时刻用户捏按 AirPods 耳机柄或按键盘 F8 键，底层 0ms 瞬间暂停，跳过大模型。

### 场景 6：歌词同步与多语种原声精读 (ROI ★★★☆☆)

在听网易云外语音乐、或研读 YouTube 外语演讲时，随时追问当下的原声词句含义与语法。

#### 实操对话示例：
> **你**：“*现在唱的这句日文歌词是什么？翻译一下。*”
> **Agent**：“*为您捕获当前播放头歌词原句：*
> 🎵 **原词**：`誰にも言えない秘密を 抱えたまま歩いてきた`
> 📖 **释义**：*一直怀揣着无法对任何人言说的秘密，就这样一路走来。*
> 💡 **语法要点**：`〜たまま` 表示保持前项状态继续进行后项动作。*”

#### 关键交互点：
- **网易云 LRC 歌词分词**：jue 内置推导 LRC 时间戳，将逐行歌词作为结构化 cues 交付；
- **时空同步定位**：Agent 通过 `status` 读取当前播放头秒数，精准锁定目标语句，杜绝错位。

### 场景 7：关键帧研读与视觉证据链 (ROI ★★★★★)

在面对前沿技术分享、Keynote 演讲、白板推导或系统架构串讲时，最关键的信息大量残留在 PPT、架构拓扑图、交互终端或代码屏幕上。若仅依赖字幕（Transcript），遇到演讲者一句口语化的“*大家请看这张架构图，左边是控制面，右边是数据面*”，纯文本模型就会陷入“盲人摸象”的认知断层。

通过 `jue frame`，Agent 具备了**端侧流式时空单帧感知能力**，能在秒级内从网络视频流中精准抽取指定时点的极简单帧，直通视觉认知模型，打通“视、听、读”一体化的事实证据链。

```
            长视频链接 (长程技术研读)
                      |
                      v
           【第 1 步：查全局路标与原声】
      “这篇演讲第 14 分钟架构图里画了什么？”
                      |
    Agent 执行 jue inspect 锁定章节
    执行 jue transcript --range 13:30-14:30 提取原声
                      |
                      v
           【第 2 步：瞬态时空抓帧】
      演讲者口述“如图所示”，画面呈现系统核心架构图
                      |
    Agent 执行 jue frame <url> --at 14:00 --width 960
    瞬态派生 One-shot mpv 单帧解码 (<80KB, ~690 Tokens)
                      |
                      v
           【第 3 步：端侧视觉感知 (read_image)】
    Agent 调用宿主工具 read_image 读取该帧图像
    精准解析拓扑节点、数据流向箭头、配置参数与代码片段
                      |
                      v
           【第 4 步：交付图文并茂的确定性证据】
    融合原声讲解与图像事实，输出带跳转链接的高保真解答卡片
```

#### 实操对话示例 1（复杂架构拓扑解析）：
> **你**：“*这个长视频第 14 分钟作者放出的分布式调度架构图，核心拓扑和通信协议是什么？*”
> **Agent**：“*已为您提取第 14:00 秒的视觉帧（直达链接：[查看 14:00 关键帧现场](https://youtube.com/watch?v=...&t=840s)）与前后原声讲解：*
>
> #### 视觉拓扑解析 (Visual Frame Evidence)
> - **控制平面 (Control Plane)**：顶部包含 3 节点 Raft 共识集群，通过 gRPC 双向流（Bidirectional Streaming）下发任务契约；
> - **调度引擎 (Scheduler Core)**：包含两级优先级队列（P0 实时任务、P1 批处理任务），带环形无锁背压隔离；
> - **数据面执行节点 (Worker Fleet)**：底部为基于 eBPF 探针的 Worker 实例，心跳周期标注为 `50ms`。
>
> #### 演讲者原声论据 (Verbatim Quote)
> > [14:18] *“Notice how the scheduler bypasses kernel network stack by directly piping tasks into the worker ring buffer.”*
> > — [Distributed Architecture (14:18)](https://youtube.com/watch?v=...&t=858s)
>
> *结论：作者正是通过画面中直连 ring buffer 的虚线箭头，证明了其相比传统 HTTP 轮询降低了 85% 的端到端调度延迟。*”

#### 实操对话示例 2（经典破壁：去幻觉与声画事实对齐）：
> **你**：“*3Blue1Brown 这个长视频第 3 分钟，屏幕上展示的神经元核心定义是什么？圆圈里的数字是多少？*”
> **Agent**：“*已为您提取第 03:00 秒的关键帧（直达链接：[查看 03:00 关键帧现场](https://youtube.com/watch?v=aircAruvnKk&t=180s)）与前后原声讲解：*
>
> #### 视觉现场证据 (Visual Grounding Evidence)
> - **图形元素**：纯黑背景中央偏左包含一个浅蓝色圆圈，内部数值确定为 **`0.8`**；
> - **排版文字**：圆圈下方清晰印有标准公式排版：**`Neuron → Thing that holds a number`**。
>
> #### 演讲者原声论据 (Verbatim Quote)
> > [02:56] *“Right now, when I say neuron, all I want you to think about is a thing that holds a number. Specifically a number between zero and one. It's really not more than that.”*
> > — [But what is a neural network? (02:56)](https://youtube.com/watch?v=aircAruvnKk&t=176s)
>
> *对比洞察：作者在口述中通篇仅泛称“0到1之间的数字”，并未读出具体数值；而屏幕画面明确以 **`0.8`** 作为神经元激活值的直观具象展示。单凭纯文本字幕模型必将遭遇信息黑洞，通过 `jue frame` + 视觉识别实现了 100% 确定性的声画互验。*”

#### 关键交互点：
- **视听融合去幻觉**：不再凭空猜测口述中“如图所示”的所指物，图像与字幕原话双重锚定，提供法庭级事实依据；
- **人机双轨交付范式**：Agent 内部使用 `path` 调 `read_image` 视觉识别；面向人类呈现时严禁在 Markdown 输出本地宿主 `/var/folders/` 私有绝对路径（避免 Web GUI 裂图），必须提供外网直达时间戳跳转链接（`&t=...s`）；
- **60% 时钟中心锚定启发式**：根据字幕切片推导抽帧时，默认建议采样中点偏后 60% 位（`at = start + (end - start) * 0.60`），避开 0.5~1.2s 转场未定型态（用户显式指定时点绝对优先）；
- **双边等比外框约束**：默认将长边等比缩放至 960（常见 16:9 视频收敛为 960×540），单张体积仅 30KB~80KB，Vision Token 预算恒定在 ~690 Tokens，避免大图撑爆上下文；
- **沙箱隔离与零泄露**：图片收容在 0700 临时目录（文件权限 0600），Agent 读完即可由同步机会式 GC 自动老化回收，零磁盘堆积；
- **秒级流式定位**：采用 mpv 单帧直接解流，无需下载 GB 级完整视频，耗时仅 1~2 秒。

### 场景 8：边听边聊——语音对话时音乐自动让位 (v2.2.0)

和语音 Agent（如 `co-s2s`）边放音乐边聊天时，Agent 开口说话前把音乐压低，说完再慢慢恢复，你不用伸手调音量。你听到的是：Agent 一开口，音乐在 0.2 秒内平滑降到原来的约 20%；它说完，音乐在 0.4 秒内平滑回到原来的音量。

#### 实操对话示例：
> **你**：（音乐在放）“帮我查一下明天的天气。”
> **Agent**：（音乐自动压低）“明天晴，最高 24 度……”（说完，音乐慢慢回来）

#### 关键交互点：
- **长对话**：Agent 开口时 `jue control duck on`，说话期间每 ≤20 秒再发一次续期，说完 `jue control duck off`；短回复可直接用脉冲 `jue control duck --duration <回复时长>`，到点自动恢复；
- **不会卡在小音量**：恢复的定时器在播放器里，不在 Agent 里。即使 Agent 崩溃、忘了发 `off`，最后一次指令之后至多 30 秒开始恢复，再经渐显时间完全回到原音量；
- **与音量互不干扰**：闪避压的是一个独立的增益级，你说“音量调到 40”照常生效，闪避结束后就是 40；`jue status` 里的 `volume` 永远是你设的音量，闪避中另有一个 `duck` 字段表示此刻的电平百分比；
- **换歌、暂停、快进都不打断闪避**：Agent 说话途中换歌，新歌也以压低的电平进入，不会突然满音量；
- **升级后的老播放器**：升级 jue 前就已在放的播放器没有闪避能力，Agent 会得到 `unavailable`，说一句“停掉再放”即可。

### 场景 9：插拔耳机时 Agent 知道声音去了哪 (v2.2.0)

插上有线耳机、连上或断开 AirPods、插拔 USB 声卡时，`jue events` 会派发一条 `audio_device_changed`，带上当前可用的输出设备拓扑列表。语音 Agent 可以据此获知“检测到 AirPods 已就绪”或在耳机断开时主动暂停。播放器底层会自动尝试迁移输出路由。

- 只在“有哪些设备”变化时报告；只在控制中心里切换默认输出（设备没增减）不会报告；
- 摘下双耳 AirPods 触发的是既有的 `paused` 事件，不是设备变化；
- 事件里的 `audio_device` 是播放器的输出选择设置（通常是 `auto`，即跟随系统），不代表声音此刻实际从哪个设备出来。

## 幕后原理：队列、检索与放毕感知

你不需要记这些，但了解它们有助于理解 Agent 为什么这样回答：

- **瞬态内存队列**：队列就是播放器（mpv）进程内存里的播放列表。播放器空闲时加歌会立刻开始放并等到出声；正在放时加歌只是排到队尾、马上返回。`stop` 或播放器退出，队列随之消失；整组放完后再加歌会从头开始，不会叠上已经放过的历史。并发同时加歌也只会启动一个播放器，一首都不会丢。
- **检索的非对称分流**：`ytsearch1:` 是 yt-dlp 自带的 YouTube 检索协议，jue 只负责转交，不含任何自研爬虫。播放器只认 `ytdl://ytsearch1:…` 写法，yt-dlp 则拒收 `ytdl://`，jue 在两边各自补上或剥掉这个前缀。只支持 `ytsearch1:`（及等价的 `ytsearch:`）；必须显式写出前缀，单独一个歌名会被当成本地文件。起播后 Agent 拿到的是解析出的标准 YouTube 链接，可以直接引用。
- **`queue_ended` 放毕感知**：播放器在最后一首自然放完（或出错）并转入空闲的那一刻派发 `queue_ended`。你主动停止、换歌导致的结束不算放完；播放器本来就空闲时，Agent 等它会立即得到“没有在播放”的回答，而不是空等。

## 异常场景自愈与智能降级指南

在真实网络环境中，平台权限、字幕缺失或网络波动是常态。Agent 会根据 jue 的四级退出码与返回信封自动进行优雅降级，绝不向你抛出晦涩的底层错误：

| 现象 / 边界条件 | 底层状态码 | 根本原因 | Agent 的自愈与降级策略 |
|---|---|---|---|
| **B 站视频无公开字幕** | 退出码 4 (`unavailable`) | B 站未公开原生 CC 字幕轨 | **自动降级为 Chapters 章节地图**：“*该视频无公开原声字幕，但我为您准备好了章节路标，您可以点播特定段落直接听。*” |
| **网易云纯音乐 / 伴奏** | 退出码 4 (`unavailable`) | 纯器乐无歌词轨 | **主动标识纯音乐并照常起播**：“*这是一首纯音乐（无歌词），已直接为您在音箱起播。*” |
| **链接失效 / 暂不支持** | 退出码 1 (`error`) | 私密视频或非媒体域名 | **引导自然语言查找**：“*该链接无法直接解析。您可以直接告诉我歌名或演讲主题，我来帮您查找可用公共源。*” |
| **外部工具缺失或网络断开** | 退出码 2 (`error`) | 本地未装 mpv/yt-dlp 或断网 | **诊断性明确提示**：“*检测到底层媒体工具或网络异常，建议检查网络连接或运行 `./install.sh` 修复依赖。*” |
| **闪避时提示 `unavailable`** | 退出码 4 (`unavailable`) | 播放器是升级 jue 之前启动的，没有加载闪避助手 | **一句话自愈**：“*播放器需要重启一下才能自动让位，我先停掉再接着放。*”（`stop` 后从原位置 `play --start`） |
| **未播放时喊暂停/快进** | 退出码 4 (`not_playing`) | 播放器处于空闲状态 | **友好提醒**：“*当前没有正在播放的音频。您可以告诉我‘放首晴天’开始播放。*” |
| **已是最后一首/第一首还要切** | 退出码 4 (`unavailable`) | 队列越界（`end of playlist` / `start of playlist`） | **如实告知并给选项**：“*这已经是队列里最后一首了，要我再加几首类似的吗？*”当前曲目不受影响。 |
| **歌名检索无结果** | 退出码 4 (`unavailable`) | `ytsearch1:` 在 YouTube 没有命中 | **换关键词或换源**：“*没搜到这首，换个写法或告诉我歌手名试试？*” |
| **不支持的检索写法** | 退出码 1 (`error`) | 用了 `ytsearch5:`、`scsearch:` 等白名单外前缀 | Agent 自行改用 `ytsearch1:` 重试，不打扰你。 |

## 终极总结口诀

- **听歌动嘴**：想听什么直接说，两行卡片看着爽；
- **暂停动手**：捏按耳机最灵光，零秒静音不用等；
- **快进快退**：报个秒数随心跳，想去哪里就去哪；
- **连着听歌**：一组歌名报出来，排进队列自己放；
- **边听边聊**：Agent 开口音乐让，说完音乐自己回；
- **长篇问点**：不用通篇读字幕，报个分钟抓原话；
- **打断追问**：走神两句不用慌，倒带重听原汁尝；
- **沉淀知识**：关键证据随手存，自动归入知识库。
